# Blender 人物制作工作流

以用户选定参考和用途为目标，交付实际可打开的工程及能够说明相似度和可用性的渲染证据。原型、静态角色、动画角色是不同完成范围。不能从脚本运行成功推断造型还原成功。

局部改善、文件重开和几何一致性检查不等于用户认可整体相似度。用户要求精细复刻时，只有主要识别特征的草模仍是中间结果；原图纹理带来的质感改善也不能证明隐藏结构正确。不要保证“完美复原”。

## 开始工作

- 读取项目说明，检查原图、已批准参考、现有模型、贴图、脚本和实际 Blender 版本。先查看图像内容，不能只凭文件名或对话中的文字描述建模。
- 对话引用不含图片时，尝试读取原对话和已知项目资源。仍无法取得目标图时，请用户补发；不要自行换一个人物继续。
- 从请求判断范围。只修脸部时保留无关身体和头发；完整人物才进入全身阶段。用途不明确而影响拓扑、绑定或交付格式时，询问这一项，同时推进不依赖回答的资源检查。
- 后续反馈持续更新当前范围和待修项。“头部和头发”不自动包含脖子；用户明确不要的部件应移除。保留用户纠正过的脸型等约束，修好一项后继续处理其余已要求的问题。
- 默认在新版本中工作，保留用户手工修改。新参考若换了角色，建立独立版本链，不沿用旧人物特征。
- 仅记录操作、复盘或更新技能时，不重新生成、修改或切换 Blender 工程；将项目路径、参数与历史证据留在项目文档，将可复用判断写入技能。

## 建模第一步：生成九视图参考

根据原图开始新角色建模时，先生成并检查 9 张独立参考图，再进入参考配准和几何制作。已有同一角色、同一版本且检查合格的九视图时直接复用，缺图只补缺项；局部修模不重复生成整套参考。用户明确调整视图范围时遵从用户要求。仅更新技能或文档不触发图像生成。

- 水平每隔 45° 一张：正面 0°、左前 45°、左侧 90°、左后 135°、背面 180°、右后 225°、右侧 270°、右前 315°；另加正上方顶视图，共 9 张。默认不生成正下方图片。
- 左右以角色自身为准：左侧鼻尖朝画面右，右侧鼻尖朝画面左。顶视相机从正上方向下看，角色前方朝画面下；不能用低头正面图代替顶视。
- 先读取 imagegen 技能并查看原图，使用内置图像生成工具，每个视角单独调用。所有视角共同引用同一原图和人物特征约束，保持脸型、五官、发型、颜色、表情及当前制作范围；只做头部和头发时不添加脖子或身体。
- 统一白底、方形画幅、完整轮廓和留白；水平视图要求相同尺度、相机高度和正交投影。逐张检查实际方向、裁切与人物特征，再横向比较轮廓、关键点和发束结构；明显错误的视图先修正，不能只按文件名验收。
- 原图保留为主基准，侧后方和顶部的隐藏结构标明为设计补全。生成图未经几何标定，存在冲突时以原图为准并记录需要建模统一的部分，不能当成严格一致的三维投影。
- 将 9 张独立图片、原图、视角名称、提示词及来源保存到项目内独立版本目录，提供可逐张查看的索引。完成参考检查后继续建模，不因生成参考图完成而结束建模任务。

## 制作和验收

开始制作时读取 [制作与验收流程](references/production-workflow.md)，按当前阶段使用对应内容，不必执行所有阶段。
使用生成脚本、批量变形、自动取景或修改现有工程时，再读取 [Blender 执行与版本可靠性](references/blender-reliability.md)，其中也包括参数中线与周期接缝检查。
用户强调原图质感、光照、腮红，或需要静态插画式局部 UV、发片透明边缘时，读取 [静态插画质感与遮挡诊断](references/static-illustration-finish.md)。
连续修发质时，按该文的“发质修正闭环”先定位责任曲面与纹理，再决定修改；保留可用基线，并区分已采用、已否定和待验证的试验。
刘海出现规则缺口、鬓发混入肤色，或顶视出现中心破洞和放射拉伸时，重点检查该文中的边界采样、面内 UV 插值和极点结构。

1. 先完成上方九视图生成与检查，再记录参考来源、可见信息、补绘内容和未知区域；检查多视图是否互相矛盾。
2. 配准参考和相机，保存单位、坐标轴、画幅、裁切、投影方式和关键点；不明视角按近似参考处理。
3. 优先复用适合角色风格、来源允许使用且实际可编辑的头部模板。先做低细节脸型与五官体积，观察正面、侧面和斜侧面，再增加密度。
4. 做完整脸部时覆盖眼球/眼面、眼睑与眼角、眉睫、鼻部、唇缝与口周、下巴和耳部；颈部衔接仅在包含脖子时制作，口腔、牙齿、视线、闭眼和表情随用途决定。
5. 以灰模、隐藏头发和固定相机渲染判断结构，再制作发型与材质。原图投射和烘焙阴影不能代替几何检查。
6. 按用户范围扩展身体、服装、配饰和绑定。脸部未达标时，不用增加全身细节掩盖核心问题；若用户明确优先全身，遵从其顺序并说明脸部状态。
7. 从同一版本实际工程输出多视图检查，分别报告视觉相似度、网格/资源有效性和用途可用性。只报告实际执行的检查。

如果一轮修形没有改善主要问题，定位是参考冲突、相机、模板结构还是修改方式的问题；更换必要的方法后再迭代。不要不断增加细分或微调参数却不比较实际渲染。没有可靠输入或工具能力不足时，说明具体缺口，保留可复用成果，不伪造完成状态。

## 工具选择

- 批量构建、参数修改、渲染、打包与检查可使用 Blender Python/CLI；交互观察、雕刻和最终打开检查可使用可用的 UI 工具或结构化接口。
- 先检查连接能力。MCP 未连接不代表 Blender 不可用；若本地 CLI 可用，可直接继续。不要把某台机器的安装路径或某次版本写成通用依赖。
- 需要补绘设定图或生成纹理时，使用当前可用的图像生成能力，并读取相应技能。保留来源和提示词，标明新增设计；补图不能当作隐藏几何的测量证据。
- 本技能不附带图像生成服务或 `imagegen` 技能。新角色缺少九视图且环境没有相应能力时，说明具体缺口并请求补齐参考或调整视图范围；可继续资源检查，不伪造已完成的参考。已有合格参考或仅局部修模时，继续不依赖图像生成的工作。
- UI 粘贴超时后先查看输入是否已经出现，再决定重试，避免重复执行。将界面状态、CLI 退出码、输出存在与实际内容分别确认。

## 交付与清理

制作交付包含当前 `.blend`、实际渲染对比、必要检查结果及简短说明。打包后重新打开最终文件，确认贴图、相机、可编辑对象和修改器状态。只对已验证用途作承诺；没有测试动画就不称为可动画角色。

用户要求清理时停止相关写入任务，枚举当前授权项目的工程和备份，优先移入废纸篓并保留恢复清单，验证残留及当前打开场景。明确清理原生 `.blend`/数字备份还是整个生成目录；范围明确的请求直接执行，不重复确认。不要将清理一个项目扩大为删除其他项目、原始参考、软件或资源包。同步文档中已经失效的工程路径。
